# Mobile project binding intake

Use these questions to create the runtime project brief. Record answers,
evidence locations, selected variants, assumptions, owners, and unresolved
decisions outside this read-only pack.

## Product and users

- What user problem, target audiences, business outcome, and measurable success
  conditions define the release?
- Which journeys are release-critical, and what is explicitly out of scope?
- Who owns product, design, technical, privacy, security, legal, and release decisions?

## Platforms and delivery

- Which platforms, form factors, OS versions, locales, and accessibility target apply?
- Is the client native or cross-platform, and what existing architecture,
  design system, analytics, and release automation must be preserved?
- Which device capabilities, offline/background behavior, notifications,
  deep links, and third-party SDKs are required?
- Which stores, enterprise channels, staged rollout, deadlines, and rollback
  constraints apply?

## Data, services, and risk

- What data is collected, generated, stored, transmitted, retained, exported,
  or deleted? Which data is sensitive or regulated?
- What authentication, authorization, APIs, backend services, payments,
  subscriptions, moderation, or account-deletion flows apply?
- Which threat model, privacy notices, consent rules, store declarations, and
  organizational policies are authoritative?

## Evidence and completion

- Which repositories, documents, environments, test accounts, device labs, and
  observability systems are available?
- What device/OS test matrix, performance thresholds, accessibility evidence,
  security checks, store metadata, approvals, and monitoring define done?
