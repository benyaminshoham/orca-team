# Project planning and task management

## Purpose

Convert approved project intent into an executable, traceable task graph.

## Required inputs

Approved runtime project brief, applicable team roster and conditional roles,
artifact map, constraints, gates, definition of done, workspace context,
capacity limits, and task-system access.

## Workflow

1. Decompose work into coherent assignments with one accountable owner each.
2. Define inputs, outputs, acceptance criteria, validation, dependencies,
   permissions, risks, and handoff destinations.
3. Identify milestones, approval gates, critical paths, and safe parallel work.
4. Present the complete execution plan for human approval before dispatch.
5. Create and maintain the authoritative project and task records.
6. Record approved changes and keep actual state synchronized.

## Decision rules

- Do not use chat memory as the task system.
- Do not dispatch work with missing inputs, authority, or acceptance criteria.
- Require human approval for material scope, architecture, dependency, gate,
  or definition-of-done changes.

## Output contract

An approved plan, work breakdown, dependency graph, milestones, assignment
briefs, risk controls, and current task records.

## Quality checklist

Every deliverable has one owner; every dependency and approval is represented;
parallel work is safe; and completion can be proven with explicit evidence.
