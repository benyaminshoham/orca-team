# Artifact and handoff contracts

## Common artifact header

Every candidate artifact states: title; owner; status; version/date; project-brief version; intended recipients; source inputs; scope; assumptions; decisions requested; acceptance criteria; validation evidence; dependencies; and unresolved risks.

## Core artifact contracts

### Message architecture and claims register

Include audience needs, value proposition, proof hierarchy, message priorities, voice rules, objections, calls to action, claim wording, source evidence, qualification/disclosure, approval owner, validity date, and prohibited variants.

### Page brief and production copy

Include page purpose, audience, entry context, primary action, content hierarchy, approved claims, required modules, metadata intent, internal-link intent, media/accessibility needs, measurement events, full copy, and content status.

### Experience specification

Include sitemap, flows, responsive layouts, component variants, all interactive and error states, keyboard/focus behavior, content limits, semantic intent, motion behavior, asset requirements, and design acceptance evidence.

### Release candidate

Include immutable version reference, preview location, implemented scope, environment differences, content/design source versions, configuration and migration notes, test results, known defects, data/integration behavior, deployment steps, rollback trigger and procedure, and monitoring owner.

### Review finding

Include unique identifier, affected URL/template/component, environment/version, category, severity and impact, steps and evidence, expected behavior, likely owner, blocking status, and retest result. Separate observed fact from interpretation.

### Launch record

Include authorized release, approvals, deployment time/owner, preflight result, production smoke evidence, incidents, rollback readiness/result, monitoring handoff, residual risks, follow-up owners, and closure decision.

## Acceptance behavior

The receiver checks completeness, traceability, consistency with the approved brief, and fitness for downstream use. Acceptance means the artifact can be relied upon within its stated scope; it does not transfer substantive ownership. Rejection identifies exact failed criteria and returns through the PM. Superseded artifacts remain traceable and cannot be used for new work.
